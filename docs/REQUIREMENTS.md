# REQUIREMENTS：TATEYAMA BASE 北条 公式サイトMVP（要件定義）

目的：貸別荘「TATEYAMA BASE 北条」の公式サイトを **1週間で公開** し、ユーザーが「信頼できる情報を見て、迷わず予約（外部）へ進める」状態を作る。

参照（ソースオブトゥルース）
- 施設・料金の一次情報：docs/INFO.md
- 意思決定（CTA文言、URL未設定時の挙動、画像方針 等）：docs/DECISIONS.md

用語メモ
- **MVP**：最小限の機能で、まず公開して価値検証する範囲。
- **LP（ランディングページ）**：1ページで必要情報をまとめたページ。
- **AC（Acceptance Criteria / 受け入れ条件）**：完成とみなすためのチェック項目。

## 1. MVPのゴール（やること）

### 1.1 事業ゴール
- 公式サイトとしての信頼感（情報が整理され、誇張がない）を担保する
- 予約導線（外部リンク）を分かりやすく提示し、迷わせない

### 1.2 ユーザーゴール（ユーザーができること）
- 施設の魅力（1棟貸し/デッキ/室内アクティビティ/レンタル/アクセス）を把握できる
- 料金（シーズン別・人数別）とキャンセル規定を確認できる
- アクセス（最寄り駅・海の近さ等）を把握できる
- 予約導線（外部リンク）が見つかる（URL未確定の場合は「準備中」と分かり、クリックできないことが明確）

## 2. 非ゴール（MVPではやらない）

- 予約機能の内製（空室カレンダー、決済、会員/ログイン、管理画面）
- 問い合わせフォームの実装（MVPでは **作らない**。問い合わせは外部LINE導線のみ想定）
- 料金シミュレーター（人数・日付入力で自動計算）
- Google Maps API 等の有料/鍵管理が必要な地図機能（まずは外部リンク or 埋め込み）
- 周辺観光の第三者画像掲載（権利/誤認リスク回避のため。手元写真のみ）

## 3. ページ構成（1ページLP or 複数ページ）

### 選択肢
- A. **1ページLP（推奨）**：公開が最速。スマホで完結し、CTA設計がシンプル。
- B. 2ページ：Home + 料金/規約（料金表が長いため分離できるが、実装/導線が増える）

### 推奨（MVP）
- **A：1ページLP**
  - 理由：1週間リリースに対して、導線/実装/コンテンツ作成の手戻りが最小。

### 1ページLPのセクション案（上から順）
1. Hero（キャッチ＋サブコピー＋主要CTA）
2. 特徴（海の近さ、駅アクセス、屋上/デッキ、室内アクティビティ、レンタル）
3. 設備（屋外 / 1階 / 2階 / 屋上 / その他）
4. 料金（宿泊料金表：シーズン別×人数別）
5. キャンセルポリシー
6. レンタル料金
7. アクセス（交通手段・最寄り駅・地図リンク）
8. 予約/問い合わせ（CTAを再掲）
9. フッター（施設名、注意事項、外部リンク）

## 5. コンテンツ要件（事実の取り扱い）

- 数値（徒歩◯分/秒など）は一次情報に基づき、表記は「約」を付ける（例：徒歩約2分、徒歩約9分）
- 一次情報が未確定の項目は、
  - 公開時点で **掲載しない**（推奨）
  - もしくは「要確認」をサイト上に出さない形で、内部タスクとして残す
- 画像は手元写真のみ（権利不明の第三者素材で穴埋めしない）

## 6. 受け入れ条件（AC）

### 6.1 体験（UX）
- スマホ表示でレイアウト崩れがない（主要ブラウザ：iOS Safari / Android Chrome）
- 予約CTAがファーストビューで視認でき、ページ下部にも再掲されている
- 料金・キャンセル・アクセスがページ内で見つけられる（見出し/目次/アンカー等で到達可能）

### 6.2 導線（外部リンク）
- `NEXT_PUBLIC_BOOKING_URL` が設定されている場合、予約CTAで外部遷移できる
- `NEXT_PUBLIC_BOOKING_URL` が未設定の場合、予約CTAは
  - 表示は残す
  - 文言が「準備中」になっている
  - クリック不可（無効化）
- `NEXT_PUBLIC_MAP_URL` / `NEXT_PUBLIC_LINE_URL` も同様に未設定時は「準備中」で無効化

### 6.3 内容（コンテンツ）
- 料金表・キャンセル規定・レンタル料金が docs/INFO.md と一致している
- 断定を避けるべき箇所（徒歩表記など）に「約」が付いている
- 設備一覧が docs/INFO.md の範囲で網羅されている（未定のアメニティは掲載しない、または注意書き）

### 6.4 SEO（最低限）
- 各ページ（1ページLPならトップ）に `title` / `description` が設定されている
- OGP（`og:title` / `og:description` / `og:image`）が設定されている（画像未確定なら暫定でも可）
- `noindex` になっていない（公開意図がある場合）

### 6.5 アクセシビリティ（最低限）
- 見出し階層が崩れていない（h1→h2→h3…）
- 画像に `alt` が付いている（未用意の画像は出さない）
- キーボード操作で主要リンク（予約/地図/問い合わせ）に到達できる

### 6.6 パフォーマンス（最低限）
- 画像が極端に重くない（元画像をそのまま巨大表示しない）
- 不要な外部スクリプトを追加しない
