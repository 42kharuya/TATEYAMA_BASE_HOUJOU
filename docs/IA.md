# IA：情報設計（Information Architecture）

役割：情報設計者
目的：公式サイトMVPで「迷わず予約（外部）へ進める」導線を明確にする。
制約：事実の厳守（一次情報は [docs/INFO.md](INFO.md)・運用方針は [docs/REQUIREMENTS.md](REQUIREMENTS.md)・意思決定は [docs/DECISIONS.md](DECISIONS.md)）。

用語
- **IA（Information Architecture）**：情報の並び順・見せ方・導線（ナビ/リンク）を設計すること。
- **CTA（Call To Action）**：予約など「次にしてほしい行動」へ誘導するボタン/リンク。
- **LP（ランディングページ）**：1ページに必要情報をまとめたページ。

## 1. 前提（確定事項）

- MVPのゴール：信頼できる情報を見て、迷わず予約（外部）へ進める。
- 予約導線：STORES 予約（URLは公開前に設定予定。万一未設定の場合は「準備中」で無効化）。
- URL未設定時の挙動：CTAは表示を残しつつ「準備中」で無効化（クリック不可）。
- 地図：住所・GoogleマップURLは確定（[docs/REQUIREMENTS.md](REQUIREMENTS.md) / [docs/FACTS.md](FACTS.md)）。
- 問い合わせ導線：公式LINE（URLは公開前に設定予定。万一未設定の場合は「準備中」で無効化）。

## 2. サイトマップ（1ページLPか、2ページ以上か）

### 選択肢

A. 1ページLP（推奨：MVP）
- `/`（Home）
  - セクション：特徴 / 設備 / 料金 / キャンセル / レンタル / アクセス / 予約・問い合わせ

B. 2ページ（情報量が増えたら）
- `/`（Home：魅力と要点＋予約導線）
- `/pricing`（料金・キャンセル・レンタル）
  - 理由：料金表が長くなり読みづらい場合に分離

C. 3ページ（将来案）
- `/`（Home）
- `/pricing`（料金・キャンセル・レンタル）
- `/access`（アクセス・地図・住所・交通手段）

### 推奨（MVP）

**A：1ページLP**
- 理由：実装とコンテンツ制作の手戻りが最小で、予約CTAの到達性を一番強く担保できる（[docs/REQUIREMENTS.md](REQUIREMENTS.md) と整合）。

## 2.1 将来すぐ複数ページ化できる設計（MVPから入れるルール）

狙い：最初は1ページLPで最速公開しつつ、将来 `/pricing` や `/access` を追加したくなった時に「リンク差し替えが最小」で済む状態にする。

### ルールA：セクションID（アンカー）を固定する

1ページLPの時点で、次のIDは固定して運用します（ページ内リンクのリンク切れを防ぐため）。

- `#booking`：予約・問い合わせ（CTA再掲）
- `#pricing`：料金（詳細）
- `#access`：アクセス

補足：将来ページ分割しても、これらのID名は「意味」として維持します（例：`/pricing` ページ内で `#pricing` を維持、など）。

### ルールB：ヘッダー/ショートカットのリンク先を1箇所で管理する

MVP（1ページLP）
- ヘッダー「料金」→ `#pricing`
- ヘッダー「アクセス」→ `#access`
- ヘッダー「予約」→ 外部（`NEXT_PUBLIC_BOOKING_URL`）

将来（2ページ化）
- ヘッダー「料金」→ `/pricing`（必要なら `/pricing#pricing`）
- ヘッダー「アクセス」→ `/access`（必要なら `/access#access`）

重要：**リンク先を各コンポーネントに散らさず、ナビ定義（設定）を1箇所に集約**しておくと、移行時はその定義を差し替えるだけで済みます。

### ルールC：分割の順番（移行手順）

おすすめの増やし方（最小手戻り）
1. まず Home（`/`）は残す
2. 料金が長くなったら `/pricing` を追加
3. アクセスを厚くしたくなったら `/access` を追加

移行時の実務（やること）
- Homeの「料金」は“要点サマリー＋リンク”だけ残し、詳細は `/pricing` に移す
- ヘッダーのリンク先を `#pricing` → `/pricing` に差し替える（ルールBで1箇所管理ならここだけ）
- 旧アンカー（`/#pricing`）で来たユーザーが迷わないよう、Home側に「料金を見る」リンクを残す

※SEO/共有リンク対策：URLを変える場合は、古いURLから新URLへのリダイレクトを用意する（検索結果やブックマークが死なない）。

## 3. Home のセクション順（ユーザーが知りたい順）

設計方針：
- 予約に必要な判断材料（料金/アクセス/人数）を「早めに」出す
- 魅力（特徴/設備/写真）は、予約判断を後押しする順に並べる
- 重要情報（料金・キャンセル・アクセス）は、ページ内リンクで即到達できる

### 確定：セクション順（1ページLP）

凡例：✅ 実装済み　🔲 未実装（今後の Issue）　♻️ 刷新予定（写真分散配置対応）

**写真分散配置方針：** 専用のギャラリーセクションは廃止し、各セクションで関連写真を添える。
「読む → 見る」がセクション内で完結することで、テキストだけの読みにくさを解消する。

## 4. CTA（予約ボタン）の配置ルール（どこに、どの文言で）

### 4.1 予約CTA（最重要）

- 文言（確定）：**ご宿泊予約**（[docs/DECISIONS.md](DECISIONS.md)）
- 遷移先：STORES 予約（URLは `NEXT_PUBLIC_BOOKING_URL`）

配置ルール（1ページLP）
1. **Hero内に必ず1つ**（ファーストビューで視認できる位置）
2. **ページ下部（予約・問い合わせセクション）で必ず再掲**
3. 長いセクション（料金表/設備）をまたぐため、**ヘッダーにも常設**（次章の「常に行ける導線」）

URL未設定時（必須仕様）
- `NEXT_PUBLIC_BOOKING_URL` 未設定なら：
  - ボタン文言は **「準備中」** に切替（要件：文言が準備中になる）
  - クリック不可（無効化）
  - 代わりに、ボタン近くに「予約（STORES）は準備中です」等の説明文を1行置く（※説明文は断定/誇張なし）

### 4.2 問い合わせCTA（任意：ただし導線は置く）

- 文言（確定）：**LINEで問い合わせ**（[docs/DECISIONS.md](DECISIONS.md)）
- 遷移先：公式LINE（URLは `NEXT_PUBLIC_LINE_URL`）

配置ルール
- 予約・問い合わせセクションに置く（予約CTAの近く）
- フッターにも置く（バックアップ）

URL未設定時
- `NEXT_PUBLIC_LINE_URL` 未設定なら：
  - 文言を「準備中」に切替
  - クリック不可

### 4.3 地図CTA（必須）

- 文言案：**Googleマップで開く**（固定文言。中身は `NEXT_PUBLIC_MAP_URL`）
- 配置：アクセスセクション内＋フッター再掲
- URL未設定時：文言「準備中」＋クリック不可

## 5. 常に行ける導線（予約/料金/アクセス）

狙い：ユーザーがページのどこにいても「判断に必要な情報」と「行動（予約）」へ戻れる。

### 推奨：常設ヘッダー（PC/スマホ共通）

- 常設項目（最小）：
  - **予約**（外部 or 準備中）
  - **料金**（`#pricing` などページ内アンカー）
  - **アクセス**（`#access` などページ内アンカー）

ルール
- 予約はボタン（目立つ）／料金・アクセスはテキストリンクでも可
- 予約URL未設定時も、ヘッダー内に「準備中」状態で表示は残す（要件準拠）

### 代替案（検討用）

- 代替1：Hero直下のショートカットのみ（料金/アクセス/予約）
  - メリット：実装が軽い
  - デメリット：スクロール後に導線が消えるため、迷いが増えやすい

- 代替2：画面右下の固定CTA（モバイルのみ）
  - メリット：予約到達性は強い
  - デメリット：「追加UI」になるため、MVPでは常設ヘッダーの方がシンプル

## 6. 決定事項

このセクションは「未確定」ではなく、下記の通り **決定** とします。

### 決定事項

1) URL未設定時の予約ボタン表示
- **採用： (a)** ボタン文言を完全に「準備中」にする
   - 理由：要件「文言が準備中になる」とズレない
   - 実装メモ：無効化（クリック不可）＋近くに短い説明文を置く

2) 料金セクションの見せ方
- **採用： (b)** 最小のサマリー＋「料金を見る」導線で詳細へ誘導する
   - ねらい：スクロール負荷を下げ、最短で予約判断→CTA到達させる
   - 実装メモ（1ページLPのままの場合）：
      - Homeの上部では「料金の要点（例：シーズン×人数で変動）」＋「料金を見る（ページ内リンク）」
      - 詳細料金表は `#pricing`（または将来 `/pricing`）に配置

3) ヘッダーの常設
- **採用： (a)** 常設ヘッダーに「予約/料金/アクセス」を置く
   - ねらい：どこからでも予約判断の材料とCTAへ戻れる
