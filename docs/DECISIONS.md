# DECISIONS（意思決定ログ）

目的：後から見返して「何を」「なぜ」決めたかを1分で追えるようにする。

書き方（短く）

- 決定：〜する
- 理由：〜だから
- 影響：どのページ/ドキュメント/実装に影響するか
- 代替案：検討した他の選択肢（任意）

---

## 今回決めるべき意思決定項目（チェックリスト）

- [x] トーン（3語）

## ログ

### 2026-03-22

- 決定：ターゲットは A（ファミリー）/B（友人グループ）/C（前泊・後泊）の複合とする
- 理由：施設の魅力（1棟貸し、屋上/デッキ、室内アクティビティ、レンタル、周辺観光・アクセス）を一つに絞り込まずに伝えられるため
- 影響：トップページのHeroで「最初に強く打ち出す順番」を別途決める／[docs/CONCEPT.md](CONCEPT.md) と [docs/COPY.md](COPY.md) の表現方針
- 代替案：メインターゲットをA/B/Cのいずれかに絞る

- 決定：差別化は「海の近さ」「駅アクセス」「屋上/デッキ＋室内アクティビティ」「レンタル」をすべて採用する
- 理由：施設の強みが複数あり、利用シーン（家族/友人/前泊後泊）ごとに刺さるポイントが変わるため
- 影響：トップページのHero/魅力セクションの構成、写真選定、見出し（コピー）
- 代替案：差別化を1〜2点に絞り、その他は下層で補足する

- 決定：コンセプト文は「海と街のどちらにもアクセスしやすい北条で、館山観光と海のアクティビティの拠点になれる、遊びもくつろぎも揃った1棟貸し。」を採用する
- 理由：施設内アクティビティの充実度と、海・街のアクセス容易さ、館山観光とアクティビティ拠点という価値を1文で同時に伝えられるため
- 影響：Heroのサブコピー、魅力セクション見出し、各ページの導入文
- 代替案：案1〜3のいずれかに寄せて短くする／要素を減らしてHeroと下層で分解して伝える

- 決定：トーンは「気軽・楽しい・アクティブ」を採用する
- 理由：ターゲット（家族/友人/前泊後泊）に対して“体験”と“過ごしやすさ”の両方を明るく伝えられるため
- 影響：Heroコピーの語尾（硬さを下げる）、見出しのテンポ、写真の選び方（動き・楽しさが伝わるものを優先）
- 代替案：「清潔・開放的・安心」寄りにして信頼感を最優先する／「上質・静けさ・余白」寄りにして大人向けに寄せる

- 決定：Heroキャッチは「海も観光もアクティビティも、遊びのベースキャンプ」を採用する
- 理由：差別化（海/アクティビティ/観光）を一言で束ねられ、トーン（気軽・楽しい・アクティブ）とも整合するため
- 影響：トップページのファーストビュー、OGPの短文、各所の見出し
- 代替案：「館山を遊び尽くす、拠点はここ。」など、より短い表現に寄せる

- 決定：予約CTA（ボタン文言）は「ご宿泊予約」を採用する
- 理由：外部予約（STORES想定）への遷移を前提にしつつ、ボタン文言として短く分かりやすいため
- 影響：トップ/ヘッダー等の予約ボタン文言（予約URLが確定次第リンク設定）
- 代替案：「空き状況・予約はこちら」で具体性を上げる／「外部サイトで予約（STORES）」で遷移先を明示する

- 決定：問い合わせCTA（ボタン文言）は「LINEで問い合わせ」を採用する
- 理由：問い合わせ先（LINE）と目的（問い合わせ）が一目で分かるため
- 影響：トップ/フッター等の問い合わせボタン文言（公式LINEのURLが確定次第リンク設定）
- 代替案：「質問する（LINE）」でカジュアルにする／「公式LINEはこちら」でリンク先を明示する

- 決定：STORES予約URLと公式LINE URLは、サイト完成後に作成・反映する（現時点では未設定で進める）
- 理由：予約/問い合わせアカウント（または公開用URL）の準備が未完了のため
- 影響：公開前チェックで「URL設定」を必須化／URL未設定の間はサイト上でCTAを非活性（準備中）または一時非表示にする
- 代替案：先にURLを作成して、開発中から本番導線でテストする

- 決定：予約/問い合わせのURLが未設定の間は、CTAを「準備中」で表示してリンク無効化する
- 理由：導線の存在は見せつつ、誤遷移や未設定のままの公開を防ぐため
- 影響：実装でURL未設定チェックが必要（未設定ならボタン無効＋表示文言を「準備中」に切替）
- 代替案：CTAを一時非表示にする

- 決定：徒歩表記は「徒歩約30秒」「徒歩約9分」のように「約」を付けて公開する
- 理由：実際の徒歩時間はルート/信号/歩行速度で前後するため、断定を避けて期待ズレを減らす
- 影響：サイト上の表記（アクセス/特徴）と、根拠情報（[docs/INFO.md](INFO.md)）の表現統一
- 代替案：徒歩分数は掲載せず「海の近く」「駅からアクセスしやすい」など定性的表現にする

- 決定：画像素材は「手元写真のみ」を使用し、周辺（海/観光）の写真は原則掲載しない
- 理由：権利と誤認リスクを最小化し、施設の実態と一致する情報設計にするため
- 影響：写真が不足する箇所は「画像準備中」で表示して無効化（第三者素材で穴埋めしない）／Heroは外観・入口の写真を主役にする
- 代替案：不足分のみ商用OK素材で補完する／周辺写真を手元撮影したものに限って掲載する

### 2026-03-24

- 決定：公開時点までに、予約（STORES）URL と 公式LINE URL を用意してサイトに設定する
	- 理由：MVPの目的（予約導線の明確化）を公開初日から満たすため
	- 影響：環境変数 `NEXT_PUBLIC_BOOKING_URL` / `NEXT_PUBLIC_LINE_URL` の設定が公開前チェックの必須になる
	- 代替案：公開当初は「準備中」で開始し、後から差し替える

- 決定：URL未設定時の予約ボタン文言は「ご宿泊予約」等を残さず、**完全に「準備中」** に切り替える
	- 理由：要件「準備中で表示して無効化」とのズレをなくすため
	- 影響：CTA実装（文言切替＋クリック不可＋補足説明文）／[docs/IA.md](IA.md)
	- 代替案：「ご宿泊予約（準備中）」のように行動名を残す

- 決定：料金は、ページ上部では **最小のサマリー** を提示し、「料金を見る」導線で詳細（`#pricing` など）へ誘導する
	- 理由：スクロール負荷を下げ、予約導線の到達性を上げるため
	- 影響：Homeの情報設計／セクション分割（将来 `/pricing` 分離もしやすい）／[docs/IA.md](IA.md)
	- 代替案：料金表を上部で全表示する

- 決定：ヘッダーに「予約/料金/アクセス」を常設し、ページのどこからでも主要導線へ戻れるようにする
	- 理由：ユーザーが迷いにくく、MVPの目的（予約導線の明確化）に直結するため
	- 影響：ヘッダーナビの実装／アンカー（`#pricing`/`#access`）管理／[docs/IA.md](IA.md)
	- 代替案：Hero直下のショートカットのみ

- 決定：チェックイン/チェックアウト時刻とアメニティ詳細は、確定するまで断定せず「整理中」としてサイトに掲載する
	- 理由：未確定事項を隠さず伝えつつ、誤情報の断定掲載を避けるため
	- 影響：掲載文章（[docs/CONTENT.md](CONTENT.md)）／必要なら公開後に差し替え
	- 代替案：未確定事項はサイト上に一切出さず、掲載しない
